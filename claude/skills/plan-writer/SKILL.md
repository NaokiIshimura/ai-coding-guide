# 実行計画作成スキル

収集した情報を基に、実装の全体像と具体的なステップを明確にする実行計画（plan.md）を作成します。

## 重要な注意事項

- **計画の作成のみを担当**: コードの実装・修正は行わない。実装は計画作成後に `tasks-execute` スキルで行う
- **日本語での記述**: 実行計画は必ず日本語で記述する
- **既存ファイルは上書きしない**: 更新する場合も新しいタイムスタンプで別ファイルとして作成し、履歴を保持する
- **機密情報の保護**: パスワード、APIキー、トークンなどの機密情報は出力しない

## 入力情報

- チケット番号またはタスク識別子（任意）
- 情報源（呼び出し元から指定される。指定がなければ会話の内容から判断する）
  - **会話の内容**: これまでの作業状況・調査結果・git差分を整理して計画にする
  - **ユーザーの要求・チケット**: 要求内容を理解し、コードベースを調査して計画にする
- 既存の仕様書（requirements.md、design.md、tasks.md）がある場合はそれらも参照

## 実行手順

### Step 1: 準備

1. **識別子の決定**
   - チケット番号が与えられている場合はそれを使用
   - 与えられていない場合は、現在のgitブランチ名から推測（例: `ABC-123`, `feature/ABC-123` → `ABC-123`）
   - 推測できない場合は `tmp` を使用
2. **出力先ディレクトリを作成**
   ```bash
   mkdir -p .claude/plans/<識別子>/
   ```
3. **既存ドキュメントの確認**
   ```bash
   ls -t .claude/plans/<識別子>/ 2>/dev/null
   ```
   - 既存の plan.md / requirements.md / design.md / tasks.md があれば、最新のものを読み込む

### Step 2: 情報収集

- タスクの目的と要件を理解する
- 会話の内容が情報源の場合は、作業状況・調査結果を整理し、git差分があれば変更内容を要約する
- 既存のコードベースを調査し、関連ファイルとディレクトリを特定する
  - 広範囲の探索が必要な場合は、Agent ツールで `Explore` エージェントを起動して調査を委譲する
- 不明点がある場合はユーザーに確認する

### Step 3: 計画作成

1. **タイムスタンプを取得（日本時間）**
   ```bash
   TZ=Asia/Tokyo date +%Y_%m%d_%H%M_%S
   ```
2. **テンプレートに沿って plan.md を作成**
   - テンプレート: `${CLAUDE_SKILL_DIR}/templates/plan.md`（**作成前に必ず Read ツールで読み込み、その構成に従う**）
   - 出力先: `.claude/plans/<識別子>/YYYY_MMDD_HHMM_SS_plan.md`

計画には以下を含める:

1. **実装の概要**: タスクの目的、実装のスコープ、期待される成果
2. **ステップバイステップの実行計画**: 各ステップの詳細な説明、ステップ間の依存関係、使用するツールやコマンド、完了条件
3. **関連する重要ファイル**: 修正対象、参照ファイル、新規作成ファイル
4. **検証手順**: 各ステップの完了条件、テスト方法、品質チェック項目
5. **注意点・リスク**: 潜在的な問題点、回避策、フォールバックプラン

### Step 4: 完了報告

- 作成したファイルのパス
- 計画の概要（ステップ数など）
- 次のステップの提案（例: `/plan.implement` で計画に基づいて実装を開始）

## 品質基準

- **明確性**: 誰が読んでも理解できる明確な記述
- **詳細度**: 実装に十分な詳細度
- **実行可能性**: 抽象的な表現を避け、すぐに実行に移せる具体的なアクションを記述
- **網羅性**: 必要なステップが漏れなく含まれている

## ファイル出力場所

- チケット番号がある場合: `.claude/plans/<チケット番号>/YYYY_MMDD_HHMM_SS_plan.md`
- チケット番号がない場合: `.claude/plans/tmp/YYYY_MMDD_HHMM_SS_plan.md`
- ファイル末尾は必ず空行で終わること
