## コンテキスト

- 現在のブランチ: !`git branch --show-current`
- 引数（JIRAのURL または チケット番号）: $ARGUMENTS
- 引数がない場合は、現在のブランチ名からチケット番号を推測してください
  - ブランチ名のパターン例: `feature/ABC-123`, `ABC-123-feature`, `ABC-123`, `feature-ABC-123`
  - 推測できない場合のみ、ユーザーにチケット番号の入力を求めてください

## タスク

JIRAチケットの情報を元に、仕様書の作成から実装までを実施してください。

**重要**: 実装を開始する前に、必ずJIRAチケットの番号を取得し、要件を正確に理解してください。

### 実施手順

1. **チケット番号の確認**
   - 引数にJIRAのURLやチケット番号があれば、それを使用
   - なければブランチ名から推測し（ABC-123形式を抽出）、推測したチケット番号をユーザーに確認
2. **JIRAからの情報収集**（mcp ガイドのルールに従い、atlassian-v2 MCP を利用する）
   - チケットの詳細情報を取得
   - チケットのコメントを取得
   - チケットのサブタスクを取得
3. **リポジトリの確認**
   - READMEを確認し、プロジェクト構成とセットアップ方法を把握する
4. **仕様書の作成**
   - Skill ツールで共通 skill `spec-writer` を呼び出し、その手順に従って requirements.md / design.md / tasks.md を作成する
   - 情報源: JIRAから収集した情報（チケット詳細・コメント・サブタスク）
   - 識別子: チケット番号（出力先: `.claude/plans/<チケット番号>/`）
5. **ユーザーの承認**
   - 作成した仕様書をユーザーに提示し、プラン通りに実施してよいか確認する
6. **ブランチの作成**
   - 承認後、Skill ツールで共通 skill `git` を呼び出し、その branch の手順に従ってチケット番号のブランチを作成・切り替える
7. **実装**
   - Skill ツールで共通 skill `tasks-execute` を呼び出し、作成した tasks.md に従って実装する
8. **結果報告**
   - 実装完了後、作業結果をユーザーに報告する（JIRAへの投稿は `/jira.issue.feedback` で行う）

### 注意事項

- 実装前にチケットの要件、受け入れ条件、関連情報を必ず確認してください
- **JIRAチケットの番号を取得せずに作業を開始しないでください**
- **仕様書作成後は必ずユーザーの確認と承認を得てから実装を開始してください**
- **既存コードの修正を行う場合は、チケットの要件を満たすための最低限の修正のみを行ってください**
  - 不要なリファクタリングや改善は避ける
  - チケットのスコープ外の変更は行わない
  - 既存のコードスタイルやパターンを極力維持する
- requirements.md, design.md, tasks.md を更新する際には、既存のファイルを上書きせず、新しいタイムスタンプ（`YYYY_MMDD_HHMM_SS_`）を付与した新しいファイルとして保存してください
