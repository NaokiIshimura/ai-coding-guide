## コンテキスト

- 引数（markdownファイルのパス）: $ARGUMENTS
- markdownファイルのパスが提供されていない場合は、ユーザーにファイルパスの入力を求めてください
- 識別子（ブランチ名）はmarkdownファイルの親ディレクトリ名を使用してください
  - 例: `/path/to/ABC-123/request.md` の場合、識別子は `ABC-123`

## タスク

markdownファイルの情報を元に、仕様書の作成から実装までを実施してください。

**重要**: 実装を開始する前に、必ずmarkdownファイルのパスを取得し、要件を正確に理解してください。

### 実施手順

1. **情報収集**
   - markdownファイルの内容を読み込み、要件・受け入れ条件・関連情報を確認する
   - 親ディレクトリ名を取得して識別子とする
   - リポジトリのREADMEを確認し、プロジェクト構成とセットアップ方法を把握する
2. **仕様書の作成**
   - Skill ツールで共通 skill `spec-writer` を呼び出し、その手順に従って requirements.md / design.md / tasks.md を作成する
   - 情報源: markdownファイルから収集した情報
   - 識別子: 親ディレクトリ名（出力先: `.claude/plans/<親ディレクトリ名>/`）
3. **ユーザーの承認**
   - 作成した仕様書をユーザーに提示し、プラン通りに実施してよいか確認する
4. **ブランチの作成**
   - 承認後、Skill ツールで共通 skill `git` を呼び出し、その branch の手順に従って識別子のブランチを作成・切り替える
5. **実装**
   - Skill ツールで共通 skill `tasks-execute` を呼び出し、作成した tasks.md に従って実装する
6. **結果報告**
   - 実装完了後、作業結果をユーザーに報告する

### 注意事項

- **markdownファイルのパスを取得せずに作業を開始しないでください**
- **仕様書作成後は必ずユーザーの確認と承認を得てから実装を開始してください**
- **既存コードの修正を行う場合は、要件を満たすための最低限の修正のみを行ってください**
  - 不要なリファクタリングや改善は避ける
  - スコープ外の変更は行わない
  - 既存のコードスタイルやパターンを極力維持する
- タスクの実行にあたって調査結果などをmarkdownファイルに出力する際には、引数で与えたmarkdownファイルと同じディレクトリに作成してください
- requirements.md, design.md, tasks.md を更新する際には、既存のファイルを上書きせず、新しいタイムスタンプ（`YYYY_MMDD_HHMM_SS_`）を付与した新しいファイルとして保存してください
