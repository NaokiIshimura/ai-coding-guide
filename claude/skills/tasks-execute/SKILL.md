# タスク実行スキル

tasks.md に定義されたタスクを読み込み、依存関係を考慮しながら順番に実装を進めます。

## 入力情報

- **tasks.md のパス**、または **計画ディレクトリのパス**（例: `.claude/plans/ABC-123/`）（必須）
- 開始タスクID（任意。例: `TASK-003`）
- 終了タスクID / 実行するタスク数の上限（任意）

パスが与えられていない場合は、ユーザーにパスの入力を求めてください。**パスを取得せずに作業を開始しないでください。**

## 実行手順

### Step 1: 準備

1. **計画ファイルの特定**
   - tasks.md のパスが与えられた場合は、そのファイルと同じディレクトリを計画ディレクトリとする
   - ディレクトリが与えられた場合は、ディレクトリ内の最新ファイルを検索する
     ```bash
     ls -t <ディレクトリ>/*_tasks.md 2>/dev/null | head -1
     ls -t <ディレクトリ>/*_plan.md 2>/dev/null | head -1
     ls -t <ディレクトリ>/*_requirements.md 2>/dev/null | head -1
     ls -t <ディレクトリ>/*_design.md 2>/dev/null | head -1
     ```
   - タスク識別子は計画ディレクトリ名を使用する（例: `.claude/plans/ABC-123/` → `ABC-123`）
2. **関連ファイルの読み込み**
   - tasks.md を読み込む
   - plan.md / requirements.md / design.md があれば参照する
   - tasks.md がなく plan.md のみの場合は、plan.md の「実行計画」の各 Step をタスクとして扱ってよいかユーザーに確認する
   - それ以外でファイルが不足している場合は警告を表示し、続行するか確認する
3. **プロジェクト構造の理解**
   - README.md と既存のコードパターンを確認する

### Step 2: タスク分析

1. **進捗状態の確認**
   - 🔴 未着手タスクをリストアップ
   - 🟡 進行中タスクがあれば継続対象とする
   - ⚠️ ブロック中タスクの原因を確認
2. **依存関係の確認**
   - 各タスクの前提タスクが 🟢 完了 になっているか確認し、実行可能なタスクを特定する
3. **実行順序の決定**
   - 優先度と依存関係を考慮し、開始タスクIDの指定があればそこから開始する

### Step 3: 実行計画の提示と確認

- 実行するタスクの一覧と順序をユーザーに提示し、実装を開始してよいか確認する

### Step 4: タスク実行

各タスクについて以下を実行します。

1. **タスク開始**: ステータスを 🟡 進行中 として扱い、タスクの詳細要件と対象ファイルを確認する
2. **実装**
   - 小〜中規模のタスクはメインのコンテキストで直接実装する
   - 対象ファイルが多い・調査量が多いなど、コンテキストを圧迫しそうなタスクは、Agent ツールで `code-implementer` エージェントを起動して実装を委譲する
     - 渡す情報: タスクID・説明・対象ファイル・完了条件、関連する requirements.md / design.md のパス
     - 依存関係がなく対象ファイルが重ならないタスクに限り、複数の `code-implementer` を並列に起動してよい
     - サブエージェントはユーザーに質問できないため、不明点があるタスクは委譲せず、先にユーザーに確認する
3. **検証**
   - 完了条件を一つずつ確認する（委譲した場合も、変更内容はメインで確認する）
   - 必要に応じてテスト・lint・型チェックを実行する
4. **完了処理**: ステータスを 🟢 完了 とし、実装メモを記録して次のタスクへ移行する

### Step 5: 進捗の保存

実行の区切り（今回の実行範囲の終了時、またはブロック発生時）に、進捗を反映した tasks.md を保存します。

- **既存の tasks.md は上書きせず、新しいタイムスタンプで新規作成する**
  ```bash
  TZ=Asia/Tokyo date +%Y_%m%d_%H%M_%S
  ```
  - 出力先: `<計画ディレクトリ>/YYYY_MMDD_HHMM_SS_tasks.md`
- 完了したタスクには以下を追記する
  ```markdown
  #### TASK-001: タスク名

  - **ステータス**: 🟢 完了
  - **完了日時**: 2025-01-02 03:04
  - **実装メモ**:
    - 実装した内容のサマリー
    - 変更したファイル
    - 注意点
  ```

### Step 6: 報告

- 完了したタスクのサマリー
- 発生した課題と解決方法（あれば）
- 残りのタスク一覧
- 次のステップの提案（例: `/git.commit.push.pr` でコミット・PR作成）

## タスク進捗状態

- 🔴 未着手（Not Started）
- 🟡 進行中（In Progress）
- 🟢 完了（Completed）
- ⚠️ ブロック中（Blocked）

## 実装ガイドライン

- CLAUDE.md のガイド（common / react / test など）とプロジェクトのコーディング規約に従う
- 自己文書化コードを記述し、コメントの言語・量は周囲のコードに合わせる
- 適切なエラーハンドリングを実装し、テスト可能なコードを作成する
- ファイル末尾は空行で終える

## 注意事項

- **スコープの遵守**: タスクに定義された範囲のみを実装する
- **既存コードの尊重**: 要件を満たすための最低限の修正にとどめる
  - 不要なリファクタリングや改善は避ける
  - 既存のコードスタイルやパターンを極力維持する
- **依存関係の厳守**: 前提タスクが未完了の場合は実行しない
- **ユーザー確認**: 不明な点があれば確認を取る

## エラーハンドリング

ブロッカーが発生した場合:

1. ステータスを ⚠️ ブロック中 に更新し、ブロッカーの内容を記録する
2. ユーザーに報告して対応方針を確認する
3. 可能であれば、依存関係のない別のタスクを先に実行する

## 出力ファイル

```
.claude/plans/<識別子>/
├── YYYY_MMDD_HHMM_SS_tasks.md   # 進捗を反映したタスクリスト
└── YYYY_MMDD_HHMM_SS_report.md  # 実行レポート（任意）
```

## 使用例

```
/tasks.execute .claude/plans/ABC-123/2025_0102_0304_05_tasks.md

- TASK-001 を実行完了
- TASK-002 を実行完了
- TASK-003 は依存関係待ち（スキップ）
- 進捗を反映した tasks.md を新しいタイムスタンプで保存
```

```
/plan.implement .claude/plans/ABC-123/ TASK-003

- 計画ディレクトリから最新の plan/requirements/design/tasks.md を読み込み
- TASK-003 から実行開始
```
